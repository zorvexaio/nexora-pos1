# تصحيحان: ضجيج IPC (heartbeat/audit) قبل الفحص الداخلي + غياب واجهة "إعادة فتح شهر الرواتب"

## 1) `main.js` — `system:rendererHeartbeat` و `audit:clientEvent`
كلا الـ handler مكتوب أصلاً ليتجاهل الاستدعاء بأمان لو `currentUser` فارغ:
```js
ipcMain.handle('system:rendererHeartbeat', (_event, state = {}) => {
  if (!currentUser) return { ok: false };
  ...
```
لكن غلاف `ipcMain.handle` (دفاع بالعمق، حوالي السطر 234) كان يرمي
`'يجب تسجيل الدخول أولاً.'` **قبل** وصول الاستدعاء لهذا الفحص الداخلي أصلاً، لأن القناتين لم
تكونا ضمن `PUBLIC_IPC_CHANNELS`. النتيجة: كل استدعاء heartbeat (كل ثانيتين من `common.js`
بأي صفحة، وهو محمّل بكل الصفحات بعد تسجيل الدخول) أو أي حدث تدقيق عميل، **في أي لحظة انتقال
قصيرة يكون فيها `currentUser` قد تصفّر مؤقتًا** (خصوصًا حول `auth:logout`، حيث تُغلق النافذة
بشكل غير متزامن بينما يستمر `setInterval` بالعمل لحظات)، كان يظهر كخطأ صاخب بسجل الـ main
process:
```
Error occurred in handler for 'system:rendererHeartbeat': Error: يجب تسجيل الدخول أولاً.
```
**الإصلاح**: أضفنا القناتين لـ `PUBLIC_IPC_CHANNELS`. هذا آمن لأن:
- لا تُعيدان أي بيانات حساسة (heartbeat لا يُعيد شيئًا سوى `{ok}`، و`clientEvent` لا يُعيد
  سوى `{success}`) — القناتان تستقبلان بيانات من الواجهة، لا تُسرّبان بيانات إليها.
- الفحص الداخلي `if (!currentUser)` بداخل كل منهما ما زال موجودًا كما هو، فلن يُسجَّل أي شيء
  فعليًا بسجل التدقيق أو حالة الـ watchdog قبل تسجيل الدخول — فقط لن يرمي الغلاف خطأ صاخبًا.

## 2) واجهة الرواتب — زر "إعادة فتح الشهر" غير موجود
`database/db.js` يحتوي `reopenPayrollMonth(monthId, reason, reopenedBy)` وهو مُعرَّض فعليًا
عبر `payroll:reopenMonth` بـ`main.js` و`window.api.payroll.reopenMonth` بـ`preload.js` — لكن
**لا يوجد أي زر بـ `renderer/pages/payroll.js` يستدعيه**. النتيجة: بمجرد أن يصير شهر الرواتب
`status='paid'` تلقائيًا (يحدث بمجرد صرف كامل مستحقات كل العاملين النشطين لذلك الشهر —
`recordPayrollPayment`، حوالي السطر 5160)، أي محاولة لاحقة لتسجيل صرف جديد (مثلاً عامل أُضيف
بعد الإقفال، أو تصحيح) تُرفض دومًا برسالة:
```
تم صرف هذا الشهر بالكامل ولا يمكن تعديل مستحقاته. إذا كان هناك خطأ، استخدم قيد تصحيح مستقل
ولا تعدّل السجل التاريخي.
```
بدون أي طريقة من الواجهة لتنفيذ ما تقترحه الرسالة نفسها. **الإصلاح**: أضفنا زر "إعادة فتح
الشهر" (يظهر فقط لو `status==='paid'`) بنفس نمط زر "إعادة فتح" الموجود أصلاً بصفحة المحاسبة
(`accounting.js`/`onReopenPeriod`) — يطلب سببًا لا يقل عن 10 محارف (يُسجَّل بسجل التدقيق عبر
`payroll_month_reopened`)، ولا يحذف أو يعدّل أي دفعة سابقة، فقط يعيد `status` إلى `'open'`
ليسمح بتسجيل صرف/تصحيح جديد.

## ملاحظة
لم تُفحص هذه التعديلات بتشغيل فعلي (لا تتوفر بيئة Electron/`npm install` هنا) — فقط
`node --check` على `main.js` و`renderer/pages/payroll.js` (نجح). يُرجى اختبارها يدويًا قبل
الاعتماد: تسجيل دخول/خروج متكرر مع مراقبة سجل الـ console (يجب ألا تظهر رسائل
`system:rendererHeartbeat`/`audit:clientEvent` بعد الآن)، وفتح شهر رواتب "مصروف بالكامل"
والتأكد من ظهور الزر الجديد وعمله.
