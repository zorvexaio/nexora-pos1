# Nexora POS v0.52.1 — Correction + Payroll Hardening

هذه النسخة تصحيحية موسعة لمحرك الرواتب، مع الحفاظ على بيانات العملاء خارج مجلد التثبيت.

## Payroll
- الحسابات النقدية في الحسابات الجديدة تعتمد minor units وتتم مزامنة الأعمدة القديمة للتوافق.
- مسار السلف V2 هو المسار المستخدم تلقائياً؛ الحركات القديمة من نوع advance لا تُخصم مرة ثانية من الراتب.
- دين الشهر يظهر في `debt_carry` بدلاً من قص الصافي وإخفاء العجز.
- الإضافي يُدخل كساعات ومعامل قابل للضبط، مع قيمة افتراضية 1.5 قابلة للتغيير من إعدادات الرواتب.
- بيانات الموظف تشمل الهوية/الإقامة، تاريخ التعيين، الجوال، القسم، IBAN، الدولة وملاحظات الرواتب.
- صرف الراتب له نموذج داخل التطبيق.
- قسيمة راتب قابلة للطباعة وحفظ PDF.
- التصفية النهائية أصبحت قابلة للإلغاء مع سجل سبب الإلغاء وعكس الحركة النقدية عند الحاجة.
- سجلات Payroll V2 أصبحت جزءاً من بروتوكول المزامنة.

## قاعدة البيانات
- schema version: 15.
- migration v15 تضيف الحقول الجديدة بشكل idempotent وتملأ minor units للسجلات السابقة.
- `foreign_key_check` مطلوب قبل تسليم نسخة للعميل.

## حدود الإصدار
الاستقطاعات النظامية الخاصة بدولة معينة (مثل GOSI أو ضريبة دخل) لا تُفعّل تلقائياً من دون إعداد سياسة الدولة، حتى لا يتم افتراض نسبة قانونية خاطئة.


### استكمال P1–P3
- كل الحسابات التشغيلية الجديدة للرواتب تُخزّن وتقارن بالوحدات الصغرى، مع ترحيل الدين عند تجاوز الخصومات/الأقساط للصافي.
- مسار السلف الحالي موحّد عبر `payroll_advances`; تسجيل حركة `advance` القديمة الجديدة مرفوض. الجداول القديمة تبقى فقط للتوافق مع قواعد بيانات العملاء القديمة.
- الإضافي أصبح ساعات × معامل قابل للضبط، مع افتراضي 1.5 وساعات عمل يومية قابلة للضبط.
- إضافة بيانات الهوية/الإقامة والتعيين والجوال والقسم وIBAN والدولة والملاحظات.
- شاشة صرف راتب داخل التطبيق، وقسيمة طباعة/PDF، وتصدير مسير Excel شهري.
- التصفية النهائية قابلة للإلغاء مع سبب إلزامي وعكس الصندوق عبر وردية مفتوحة.
- مزامنة Payroll V2 أضيفت إلى جميع كيانات الرواتب، مع حماية الفرع وUUIDs.
- تم استبدال `prompt/confirm` في شاشة الرواتب بنافذة موحدة.

### بوابات لم تُعلن كمكتملة
- توقيع Windows Authenticode يحتاج شهادة الإصدار على جهاز Windows.
- اختبار الطابعة/NSIS/التحديث الفعلي يحتاج جهاز Windows وحزمة native مثبتة.
- GOSI/الضرائب والإجازات والحضور والبصمة وطرفية الدفع وموفّر الفاتورة الإلكترونية الحقيقي تحتاج سياسة دولة/مزوداً محدداً؛ لم يتم اختراع نسب أو تكاملات غير موثقة.
